# Milestone 8 persistence notes

This file is append-only project evidence for the PostgreSQL M8 sidecar.

## M8-D001 — Keep assessment proof outside protocol 0.1

Assessment policy, trusted assessor registration, receipt, telemetry, and
artifact identity rows are additive `agent_feed` tables. Producer lifecycle
tables and protocol `0.1` envelopes remain unchanged.

## M8-D002 — Authority is a trusted composition-root lookup

`submitAssessment` receives only an exact registered assessor-version context.
It never accepts assessor identity, type, independence, or technical run status
from the submission. The repository snapshots authority from the immutable
registration row and PostgreSQL repeats that comparison for direct SQL.

## M8-D003 — Technical and quality proof remain separate

Assessment receipts retain the assessment verdict and join `runs.status` only
for a read-time technical status. Reassessment appends a new receipt and does
not update the run or prior receipt.

## M8-L001 — Store core canonical policy bytes

The repository stores both normalized policy JSON and the exact canonical JSON
bytes emitted by `@agent-feed/assessment-core`. The database verifies the
stored hash against those bytes instead of inventing a second JSON
canonicalization algorithm.

## M8-L002 — Unknown telemetry is not zero

`unknown` and `not_applicable` usage states persist a NULL value. `observed`
requires a non-negative safe value and non-unknown provenance; both repository
validation and database checks enforce this invariant.

## M8-L003 — Preserve the pure-core boundary at the adapter

The adapter retains core aliases long enough for conflicting aliases and
unknown top-level fields to fail closed. Optional usage keys use the normalized
metric as a deterministic persistence key, while timestamps and artifact media
types remain intact. A trusted context tenant binds the submission tenant;
policy compatibility rejects unknown independence and budgets forbidden by a
`not_applicable` policy.

## M8-A001 — Acceptance boundary

Live PostgreSQL acceptance is run only when `AGENT_FEED_DATABASE_URL` points to
a disposable database. Without that URL, structural/unit checks run and the
live test is explicitly skipped rather than treated as acceptance.

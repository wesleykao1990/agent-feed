# Milestone 5 bug and gap log

Started: 2026-08-18. This log is append-only.

| ID | Symptom / impact | Resolution and regression | Status |
|---|---|---|---|
| M5-001 | GitHub users had to assemble MCP dependencies, database variables, scoped credentials, and a protocol-clean command manually. | Added the root operator CLI, private generated runtime, Compose profile, doctor, and installation runbook. | Resolved locally |
| M5-002 | A naive private-file helper could chmod an arbitrary custom parent directory. | Confine setup config targets to the selected runtime tree and chmod only runtime-owned directories. | Resolved; path-boundary test |
| M5-003 | Forced writes could follow a symlink and overwrite a file outside the runtime. | Reject symlink config, database credential, and generated targets before any write. | Resolved; hostile symlink test |
| M5-004 | A direct `--database-url` places credentials in command history. | Add `--database-url-file` and require an owner-only regular file. | Resolved; file permission/conflict tests |
| M5-005 | Regenerating the bundled PostgreSQL password during `--force` would leave a persistent volume configured with the old password and make the new URL unusable. | Preserve existing database and producer credentials unless an explicit replacement is supplied. | Resolved; upgrade regression |
| M5-006 | The earlier ChatGPT runbook required manual environment exports and targeted the low-level launcher. | Make the generated credential-free wrapper the normal tunnel target and link to the GitHub installer. | Resolved in documentation |
| M5-007 | `doctor` checks socket reachability rather than authentication, migrations, or lifecycle semantics. | State the limit explicitly; retain MCP startup and live integrated gates as authoritative evidence. | Accepted boundary |
| M5-008 | At the M5A checkpoint, Supabase/SQLite portability, retention/deletion, audit export, metrics, and dashboard work remained unimplemented. | Added the scoped reference/contract slices and a separate completion record; do not broaden M5A or local-compatible evidence into hosted production claims. | Resolved as an implementation gap; production proof remains separate |
| M5-009 | Inheriting the complete parent environment would pass unrelated credentials, including the tunnel control-plane key, into the MCP child. | Build the child environment from a small OS/TLS/PostgreSQL-certificate allowlist plus exact Agent Feed variables. | Resolved; environment isolation test |
| M5-010 | Path containment alone does not reject a runtime directory or nested directory that is itself a symlink. | Reject symlink runtime/directory components before creating or writing generated state. | Resolved; linked-runtime regression |
| M5-011 | Setup initially accepted stream IDs outside the protocol schema and silently ignored unknown command flags. | Reuse the protocol `0.1` stream pattern and reject unknown/duplicate options per command. | Resolved; parser and invalid-stream regressions |
| M5-012 | An external PostgreSQL URL without a username depended on an ambient OS identity that the isolated MCP child correctly does not inherit. | Require the database principal explicitly in every configured URL. | Resolved; URL regression and live wrapper retest |
| M5-013 | The first sample-secret guard classified the documented long `replace-with-...` placeholder as a real credential. | Parse only secret-bearing variables, allow explicit placeholder words, and reject a real-looking adversarial value. | Resolved; architecture regression |
| M5-014 | The host's Python 3.14 lacked `setuptools`, so the M3 wheel smoke failed after all source/package tests passed. | Rerun the no-skip gate through `uv` with the repository's declared `requirements-dev.txt`; the isolated wheel install/import passed. | Resolved validation environment |
| M5-015 | CLI option mapping included absent values as `undefined`; spreading them over preserved upgrade state could reset a custom tenant, producer, stream, or PostgreSQL port during `--force`. | Merge only explicitly defined values over the existing configuration and exercise absent CLI-shaped fields in the force-upgrade regression. | Resolved |
| M5-016 | The first hosted run passed but warned that the Node 20 runtimes in `actions/checkout@v4` and `actions/setup-node@v4` were deprecated. | Verify the current official releases and update checkout, setup-node, and setup-python consistently to v7; retain hosted clean-checkout validation. | Resolved; replacement run `32128438231` green without the annotation |
| M5-017 | The M5A roadmap still described portability, retention, audit, metrics, and dashboard work as entirely unimplemented after the new reference modules existed. | Add the Milestone 5 completion record, update the root/project roadmap, and preserve the distinction between implementation evidence and deployment proof. | Resolved in documentation; hosted proof remains separately open |
| M5-018 | The full M5 runner cannot establish live operations or Supabase-compatible evidence without `AGENT_FEED_OPERATIONS_DATABASE_URL` or `AGENT_FEED_DATABASE_URL`. | Keep the runner fail-closed and document the required disposable PostgreSQL proof; do not add a skip mode. | Resolved for local acceptance; URL remains a required prerequisite |
| M5-019 | The first operations architecture run rejected three source-marker spellings that had drifted from the implementation: `terminal envelope`, `dashboardSnapshotFromMetricSnapshot`, and `MAX_RESPONSE_BODY_BYTES`. | Align the checker markers with the implementation (`terminal run envelope`, `mapMetricSnapshotToDashboardSnapshot`, and the bounded response constant), then rerun the guard. | Resolved; operations architecture guard 7/7 |
| M5-020 | A local PostgreSQL-compatible Supabase proof could be mistaken for production acceptance. | Split static, local-compatible, and hosted evidence in the completion record; require project-specific migration, health, liveness, Edge, and rollback receipts for hosted acceptance. | Accepted boundary; hosted proof open |
| M5-021 | A second retention worker could interpret another worker's valid `in_progress` claim as a failed item and finalize the job prematurely. | Leave the job `executing` while any item is in progress, and verify with two real PostgreSQL clients that only the claimant invokes the external adapter. | Resolved; unit and live concurrency regressions |
| M5-022 | The isolated PostgreSQL adapter initially added composite tenant constraints as `NOT VALID` without completing validation. | Explicitly validate all tenant foreign keys and the opaque storage-reference check before recording migration completion. | Resolved; live constraint validation assertion |
| M5-023 | The Supabase relay bounded producer requests but initially buffered an unbounded upstream response. | Bound both declared and streamed upstream bytes and reject direct `response.arrayBuffer()` buffering in the static gate. | Resolved; 2 MiB response ceiling |
| M5-024 | A scheduled Rewards occurrence failed before `begin_run` because the prior tunnel process had stopped, while profile doctor and binary-presence checks still passed. | Run the private acceptance tunnel under a login-persistent supervisor; make `doctor --require-tunnel` fail closed unless it proves the PID, live/ready endpoints, and an authenticated poll; then verify a ChatGPT-delivered zero-finding lifecycle in PostgreSQL before resuming the task. | Resolved; supervised restart, operator regressions, live doctor, and run `d6319150-cb23-4177-888f-529ff084d2c0` passed |
| M5-025 | The first `launchd` start exited with code 127 because service processes do not inherit the interactive Homebrew `PATH`, so the MCP launcher could not find Node.js. | Set an explicit minimal service `PATH` containing the installed Node.js directory; verify the stdio MCP child starts without raw payload logging. | Resolved; supervised startup and ready checks passed |
| M5-026 | `KeepAlive.SuccessfulExit=false` did not restart tunnel-client after a clean `SIGTERM`, leaving the route offline despite a nominal keepalive configuration. | Use unconditional `KeepAlive`; a controlled termination produced a new tunnel PID and returned to control-plane-poll-ready state. | Resolved; restart regression passed |
| M5-027 | `doctor --require-tunnel` previously accepted a missing daemon because it checked only `tunnel-client --version`. | Require explicit health-URL and PID files, invoke structured `tunnel-client health --require-control-plane-poll --json`, and reject missing, malformed, partial, unhealthy, or nonzero results without printing raw output. | Resolved; fail-closed unit cases and live supervised-tunnel proof passed |
